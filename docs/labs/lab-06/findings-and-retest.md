# Findings, corrections and retests

**No findings or retests are recorded yet.** A blank template does not
establish that no defects were found.

## Finding record

For every observed failure record product, finding ID, reporter, time and
channel; tested URL, commit and revision; case and requirement; synthetic
inputs and numbered reproduction steps; expected and actual results; severity
with user impact; and sanitized evidence. Record delivery and acknowledgement.

| Direction / finding | Case / tested version | Actual result / evidence | Severity / disposition | Retest |
|---|---|---|---|---|
| None recorded | Not recorded | Not observed | Not assessed | Not run |

Classify each received finding as accepted defect, duplicate with a link to
the original, not-defect with contract-based reasoning, or enhancement
outside the agreed Sprint 1 scope. Reproduce or clarify before dismissing.
Do not classify a failed agreed requirement as an enhancement.

## Correction and independent retest

For an accepted defect, record its issue and source version; a meaningful
regression test failing before the fix (RED); the same test passing after the
fix (GREEN); broader regression results; reviewed PR and CI; deployed commit
and revision; and an independent retest with actual results and evidence.
Critical/major defects block acceptance until resolved and retested. Minor
limitations must be fixed or explicitly accepted by the independent UAT team.

If no genuine defect is found, record the actual UAT outcome and ask the
instructor/TA about a separate controlled exercise. Do not invent a defect or
modify the live assessed release to create one.
